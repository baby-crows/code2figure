Scout 의 역할

아이디어 수렴부터 산출물 검증까지 전 단계를 Scout 한 환경에서 진행하였다. 각 단계는 개별 도구로 치환할 수 있으나, 한 환경에서 진행할 경우 앞 단계의 맥락이 유지된 상태로 다음 단계를 이어갈 수 있다. 예를 들어 스킬 설계 근거를 정한 세션이 그대로 실행 결과를 판독하고, 그 판독 결과가 다시 페이지 정리 기준이 되었다. 자료를 옮기고 다시 설명하는 과정 없이 복잡한 작업을 이어서 수행할 수 있었다. 판단과 설계는 사람이 하였고 Scout 는 아래 작업을 수행하였다.

단계Scout 가 수행한 것사람이 판단한 것
아이디어 수렴 M365(메일·회의·문서), Notion, 로컬 파일에 흩어진 자료를 한 세션에서 조회·대조. 자료가 있는 위치마다 도구를 바꾸지 않고 한 맥락에서 종합 무엇을 문제로 잡을지, 어떤 형태의 산출물이 필요한지
스킬 제작 정본 도면 25장·22장 실측, 규칙 초안 작성, 예시 XML 작성, 검사 스크립트 7종 구현 T1/T2 분류 축, 게이트를 4단계로 나눈 구조, 판정 주체를 분리한다는 결정
실험 실행 저장소 10건에 대해 신규 세션에서 스킬 실행. 코드 판독, 도면 생성, 게이트 4종 수행, 실행 보고서 작성 대상 저장소 선정, 블라인드 조건, 프롬프트 고정
검증·정리 실행 화면 캡처(총 1,184프레임), 프레임 선별, 클릭스루 페이지 생성, 정답지 대조표 작성, 고객 비노출 항목 제거 무엇을 고객에게 보이고 무엇을 내부 기록으로 남길지
산출물인 스킬 자체는 특정 환경에 종속되지 않는다. SKILL.md 와 스크립트로 구성되어 있어 다른 에이전트 환경에서도 동일하게 동작한다. Scout 는 이 스킬을 만들고 검증하는 과정 전체를 한 환경에서 수행하기 위한 수단으로 사용하였다.
