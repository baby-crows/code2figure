1. Scout 란?

Microsoft Scout 는 당신의 노트북에서 돌아가는 자율 에이전트입니다. 파일을 읽고 쓰고, 셸을 실행하고, 브라우저를 조작하고, 당신의 권한 그대로 메일·캘린더·Teams·SharePoint 에 접근해서 요약이 아니라 결과물을 만들어 냅니다. 그리고 당신이 자리에 없을 때도 Automations 와 Heartbeat 로 계속 일합니다.

Scout 가 강한 상황

자료가 여러 곳에 흩어져 있을 때메일·회의록·SharePoint·로컬 파일을 한 세션에서 모아 대조한다. 도구를 옮겨 다니며 다시 설명할 필요가 없다.
결과물까지 만들어야 할 때요약에서 끝나지 않고 문서·표·코드·페이지를 실제 파일로 낸다.
반복되는 확인 작업Automations 와 Heartbeat 로 정해진 시각에 스스로 실행하고 결과만 보고한다.
긴 작업을 이어서 해야 할 때앞 단계의 판단이 유지된 채로 다음 단계가 이어진다. 이 스킬 제작이 그 사례다.

① Build

스킬을 만드는 과정

무엇을 그릴지 판단하는 기준을 세우고, 예시와 검사 장치를 만들고, 처음 보는 저장소 10건으로 검증하기까지

② Use

만든 스킬을 쓰는 과정

저장소 경로 하나만 주면 코드를 읽고, 도면을 그리고, 검사 4단계를 통과시킨 뒤 편집 가능한 파일로 냅니다

(1) “코드만으로 논문 Figure 를 만들어줘” — 스킬 만들기

판단과 설계는 사람이 하고, 실행과 측정은 Scout 가 했습니다. 각 단계는 개별 도구로 치환할 수 있으나, 한 환경에서 진행하면 앞 단계의 맥락이 유지된 채 다음 단계로 이어집니다.

단계Scout 가 수행한 것 사람이 판단한 것
아이디어 수렴M365(메일·회의·문서), Notion, 로컬 파일에 흩어진 자료를 한 세션에서 조회·대조무엇을 문제로 잡을지, 어떤 형태의 산출물이 필요한지
스킬 제작정본 도면 47장 실측, 규칙 초안 작성, 예시 XML 작성, 검사 스크립트 7종 구현T1/T2 분류 축, 게이트를 4단계로 나눈 구조, 판정 주체를 분리한다는 결정
실험 실행저장소 10건에 신규 세션에서 스킬 실행. 코드 판독, 도면 생성, 게이트 4종, 보고서 작성대상 저장소 선정, 블라인드 조건, 프롬프트 고정
검증·정리실행 화면 1,184프레임 캡처, 프레임 선별, 결과 페이지 생성, 정답지 대조표 작성무엇을 공개하고 무엇을 내부 기록으로 남길지
방향을 바꾼 실측 하나. 자체 점검 항목을 44개까지 늘렸는데도 시험작 4편 중 4편이 그대로 통과했습니다. 늘려야 할 것은 항목이 아니라 심사하는 쪽이었고, 그래서 그림을 그린 에이전트가 아닌 다른 에이전트가 보고서도 의도도 없이 그림만 보고 판정하게 했습니다. 이 게이트가 실전 10건 중 4건을 반려했습니다.
